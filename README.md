# 蓝晒工作室 · 开放征稿与匿名评审台

一个零外部依赖（仅 Node.js 内置模块）的征稿与盲评系统：作品分组别提交、截止锁定、评审只见编号、
按专长均衡分配并自动回避、同作品至少三人独立评分、去最高最低取平均、按组别配额 + 最低分定稿、
定稿锁定后仅允许同组候补顺位递补。

## 运行

```bash
node --version        # 需要 Node >= 18（在 18/20/22+ 行为一致）
npm start             # 默认 http://localhost:3040
npm test              # 跨版本测试运行器，发现并运行 test/ 全部用例；失败返回非零
```

> 测试为什么用 `scripts/run-tests.mjs`：较新的 Node（22+）会把 `node --test <目录>` 的目录
> 参数当成待执行模块，而旧版（20）需要显式文件。运行器枚举 `test/*.test.js` 后以显式文件
> 列表调用 `node --test`，并在自身被 `node --test` 嵌套调用时清除 `NODE_TEST_CONTEXT`，
> 两个版本都能稳定发现并运行全部用例，子进程退出码原样透传。

首次启动会在 `data/cyanotype-review.json` 生成演示数据：

- **2025 年度展**：已定稿，可直接查看榜单并演示「退出 → 同组顺位递补」。
- **2026 夏季征稿**：征稿中，可走完整流程（投稿 → 锁定 → 分配 → 回避/补位 → 评分 → 定稿）。

页面右上角可切换演示身份（作者 / 评审 / 管理员），身份通过 `X-User-Id` 请求头传递（仅用于演示）。

环境变量：`PORT`、`DB_PATH`、`CALL_2026_DEADLINE`、`REVIEW_FAKE_NOW`（固定当前时间，测试截止边界）。

## 六个页面

| 标签 | 角色 | 内容 |
|---|---|---|
| ① 征稿 | 作者 | 按组别投稿、查看本人作品与征稿状态；重复提交被拒 |
| ② 分配 | 管理员 | 到点锁定、专长均衡分配、回避矩阵预览、评分进度 |
| ③ 评分 | 评审 | 只见编号与作品内容（无作者信息），1–100 整数分，可定稿前改分 |
| ④ 回避 | 评审 | 主动回避并登记原因，系统提示需补位 |
| ⑤ 榜单 | 管理员/公开 | 去极值均分、原始分、配额与最低分结果；定稿锁定 |
| ⑥ 递补 | 作者/管理员 | 入选者退出后，同组候补按顺位自动递补 |

## 核心规则的落点

- **截止锁定**：`createdAt <= deadline` 可提交（边界时刻含）；到点后管理员可锁定，锁定后内容冻结、
  不能再投稿/自撤。征稿状态机：`open → locked → assigned → finalized`，非法转移返回 `409 invalid_state`。
- **匿名**：锁定后评审接口剥离作者姓名/机构，只返回编号、标题、媒介、阐述；评审只能看到分配给自己的作品。
- **均衡分配**（`assignReviewers`）：候选必须具备该组专长且无回避；作品按「合格评审稀缺度」升序处理，
  每件作品逐位选择当前负担最小的评审；任一作品凑不够 3 人则**整批回滚**，不留半成品。
- **回避**：同机构，或当前年份 − 合作年份 < 2（两年内）合作即排除；评审也可在分配后主动回避，
  再次运行分配即补足名额，已回避者不会被重复分配。
- **评分**：1–100 整数；同一评审对同一作品仅一次有效评分，重复/并发重试返回 `409 already_scored`
  （写事务串行化，见下）；定稿后改分一律拒绝。
- **均分**：去掉一个最高分、一个最低分后取算术平均（3 人时即中位数），不足 3 个有效分不产生均分、不能定稿。
- **定稿**：须同时满足每组配额与最低分；组内按均分降序、同分按提交先后（`createdAt` 升序）排序，
  前 quota 名入选，过线但超额者进入候补链。定稿要求每件在途作品都有 ≥3 个独立评分。
- **递补**：定稿后入选者退出（`selected → retired`），只能由同组 `waitlisted` 中顺位第一者补入，
  不能跨组或人工指派；无候补则名额空缺。

## 并发、重复提交与重启恢复

- **写串行化**（`src/store.js`）：所有写操作进入同一条 Promise 链，读-改-写不会交错；
  落盘采用「临时文件 + `rename`」原子替换，写一半崩溃不会损坏 JSON；失败事务回滚内存状态。
- **乐观版本号**：每个状态对象带 `version`，写事务可校验 `expectedVersion`，过期写入返回
  `409 version_conflict`。
- **幂等键**：写请求可带 `Idempotency-Key` 头，相同键的重试原样回放首次成功响应（随盘持久化，
  重启后仍生效）；业务报错不占用幂等键。
- **重启恢复**：进程不持有未持久化状态，重启后从同一 JSON 读回全部作品、分配、分数、榜单、递补与幂等键。

## HTTP 接口

身份：所有写接口与评审/作者接口需 `X-User-Id`；写接口接受 `Idempotency-Key`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 组别、人员、当前身份 |
| GET | `/api/calls` / `/api/calls/:id` | 征稿列表 / 详情（按角色裁剪可见作品与作者信息） |
| POST | `/api/calls/:id/submissions` | 作者投稿（201；重复 409；截止/锁定 422/409） |
| POST | `/api/calls/:id/lock` | 管理员到点锁定（未到点 422） |
| POST | `/api/calls/:id/assignments` | 执行/补足分配（合格评审不足 422，整批回滚） |
| GET | `/api/calls/:id/conflicts` | 管理员回避矩阵（他人 403） |
| GET | `/api/me/assignments?callId=` | 评审本人的评分队列 |
| GET | `/api/submissions/:sid` | 作品详情（评审为匿名视图） |
| PUT | `/api/submissions/:sid/score` | 提交评分（越界 422；重复 409；未分配 403） |
| PATCH | `/api/submissions/:sid/score` | 定稿前改分（定稿后 409） |
| POST | `/api/submissions/:sid/recuse` | 评审回避（已评分/已回避 409） |
| POST | `/api/submissions/:sid/withdraw` | 截止前作者撤回；定稿后为「退出 + 顺位递补」 |
| POST | `/api/calls/:id/finalize` | 定稿锁定（评分不齐 422） |
| GET | `/api/calls/:id/results` | 榜单（公开） |
| GET | `/api/audit` | 审计日志（仅管理员） |

错误形态统一为 `{ error, message, details }`，状态码：400 非法请求、401 未登录、403 无权、
404 不存在、409 冲突/非法状态、422 业务规则不满足。

## 代码结构

```
src/
  errors.js   # ApiError 与 400/403/404/409/422 工厂
  store.js    # JSON 原子持久化 + 写串行队列 + version 乐观并发
  seed.js     # 演示数据（含同机构/合作/回避/旧榜候补链等对照样本）
  domain.js   # 纯领域逻辑：提交、锁定、分配、回避、评分、均分、定稿、递补
  server.js   # HTTP 路由、身份、幂等键、静态首页
public/
  index.html    # 六标签单页应用（ES module，无构建、无框架）
  app-utils.js  # 页面纯工具：身份的 localStorage 持久化、榜单分数健壮渲染（可被单测直接 import）
scripts/
  run-tests.mjs   # 跨版本测试入口（枚举用例文件、透传失败退出码）
test/
  domain.test.js     # 领域单元测试（trim 均分、回避、分配、定稿、递补等）
  http.test.js       # HTTP 端到端（并发评分、幂等重试、旧榜分数补全、重启恢复等）
  app-utils.test.js  # 页面工具（刷新后身份保持、榜单缺分数不崩）
  entry.test.js      # 测试入口自身的发现/退出码契约
```
